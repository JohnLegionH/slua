## What changed since 0.3.1 (API version unchanged at 5)

The exports, their signatures and the API version are the same as in 0.3.1, with one addition: the export `slua_restore_note`. A host that needs API version 5 loads this library as it loaded the last one, and a host that does not look up the new export is not affected.

1. A saved script state no longer fails to restore when the host binds more functions than it did when the state was saved. The state header (format version 2) now lists the host functions the state holds, so a restore is refused, with the function's name, only when the state holds a function this build no longer provides or binds it the other way (plain or pausing). Before, any change to the hash of the whole list of bound functions refused the state and the script started fresh.
2. A state written by 0.3.1 (format version 1) is still read. It carries only the hash of the list, so it restores when the list is the same; when the list has changed it restores unless it mentions a function that this build binds as pausing, and if the Executor cannot rebuild it the script starts fresh and the note says the list had changed.
3. New export `slua_restore_note` copies the reason the last `slua_restore` of a script refused its state into a buffer, so a host can show why a state was set aside and offer to try it again. A library without it answers an entry-point error, which a host treats as no reason given.
