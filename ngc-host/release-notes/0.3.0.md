## What changed since 0.2.0 (API version 4 to 5)

The version check is exact: a host that needs API version 5 refuses a library of another version and names both numbers.

1. New export `slua_set_host_functions` (and `Host.SetHostFunctions` in the test binding). The host gives the LSL compiler the os, iw and bot functions it supplies, one per line in the form of `builtins.txt` (`integer osAddOne( integer n )`). LSL compiled with the runtime's compiler can then call them as it calls `ll` functions. A call to `osName`, `iwName` or `botName` runs the host function registered as `ossl.Name`, `iw.Name` or `bot.Name`, which an SLua script calls by that name. `ll` and `llcompat` stay the runtime's own: a line that names an `ll` function, or any name that is not os, iw or bot followed by a capital letter, is refused and the earlier list stays.
2. With a list set, a name that is neither in the list nor an `ll` function fails to compile with its line number. A host that sets no list gets what API 4 gave: an LSL call to an os, iw or bot function is refused with the text that points at the engine that runs such scripts.
3. The LSL compiler (`Compiler/src/LSLCompiler.cpp`) takes the module of a builtin call from its prefix: `ll` for the runtime's functions, `ossl`, `iw` or `bot` for the host's. Because that changes a file of the parent tree, `ngc-host/LL-RUNTIME-PIN` now names the commit that carries the change and the stamp's runtime part is that commit. Scripts saved by an earlier release start fresh once (the API part of the stamp changed as well).
4. A release's change list now comes from a file at the tag, `ngc-host/release-notes/<version>.md`, and is added to the generated release notes. A version without a dash is refused without the file.
